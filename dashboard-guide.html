01

큰 그림 — 넷이 하는 일

이 그림 하나만 머리에 넣으면 나머지는 따라옵니다

먼저 말 다섯 개만

낯선 말이 나오면 여기로 돌아오시면 됩니다.

  • HTML 파일 — 웹 화면 하나가 통째로 든 파일입니다. 더블클릭하면 브라우저에 화면이 뜹니다. 메모장으로 열면 글자만 잔뜩 보이는데, 그게 화면을 그리는 설명서입니다.
  • 깃허브 — 파일을 올려 두는 인터넷 창고입니다. 무료입니다.
  • 저장소 — 그 창고 안의 서랍 한 칸입니다. 대시보드용으로 하나 만듭니다.
  • 파이어베이스 — 구글이 주는 자료 보관함입니다. 학생·출결이 여기 쌓입니다. 이것도 무료입니다.
  • 배포 — 올린 파일이 인터넷 주소로 뜨는 것. 자동으로 됩니다.

대시보드는 HTML 파일 하나입니다. 그 파일 하나에 화면도, 계산도, 자동채점도 다 들어 있습니다. 그런데 파일 하나만으로는 두 가지가 안 됩니다.

  • 남이 못 봅니다. 내 컴퓨터에만 있으니 학생도 학부모도 못 엽니다.
  • 자료가 안 남습니다. 출석을 찍어도 파일을 닫으면 사라집니다.

이 둘을 메우는 것이 깃허브와 파이어베이스입니다.

한 줄로

깃허브는 화면을 담아 두는 곳, 파이어베이스는 자료를 담아 두는 곳입니다. 화면은 가끔 바뀌고 자료는 매일 바뀌니, 담는 데를 갈라 놓는 것입니다.

각각을 조금 더

이름하는 일없으면
깃허브파일을 올려 두고, 언제 무엇을 고쳤는지 다 남긴다고치다 망가뜨리면 되돌릴 수 없다
깃허브 페이지그 파일을 주소로 띄워 준다나만 볼 수 있다
파이어베이스학생·출결·점수를 담고, 어느 기기에서 열어도 같게 보여 준다학원 컴퓨터에서만, 그것도 지우면 끝이다

깃허브 페이지가 따로 나오는 까닭

깃허브는 창고일 뿐이라 그대로는 화면이 안 뜹니다. 창고 문을 열어 인터넷에 내보이는 스위치가 깃허브 페이지이고, 그건 깃허브 안에 있는 기능이라 따로 가입할 것이 없습니다. (김병진T는 여기에 Vercel을 씁니다. 하는 일은 같고 조금 더 빠릅니다 — 11번에 적었습니다.)

02

왜 이 길인가

이미 있는 것들로 안 되는 까닭

이미 쓰는 것막히는 자리
엑셀 · 구글시트나만 봅니다. 학생·학부모에게 줄 화면이 안 나오고, 자동채점이나 유형분석 같은 것을 못 붙입니다.
노션 · 기성 관리 프로그램남이 정한 칸에 내 학원을 맞춰야 합니다. 「우리 반 데일리 테스트 유형별 정답률」 같은 것은 못 만듭니다.
서버를 빌려서 제대로돈이 들고, 서버가 죽으면 내가 고쳐야 합니다. 그걸 배우다 학원 일을 못 합니다.

지금 길은 이 셋의 가운데입니다. 돈이 안 들고(무료 한도 안에서), 관리할 서버가 없고, 내가 원하는 것을 그대로 만들 수 있습니다. 그리고 코드는 AI가 씁니다. 선생님이 하실 일은 무엇을 만들지 정하고, 올리고, 고쳐 달라고 말하는 것입니다.

실제로 이렇게 굴러갑니다

김병진T의 대시보드는 HTML 파일 한 개(약 9,800줄)입니다. 그 한 파일 안에 학생 관리·출결·숙제· 테스트·진도·리포트·오답 유형분석이 다 들어 있습니다. 학생용 앱과 학부모 링크는 그 옆에 파일을 하나씩 더 둔 것이고, 넷이 같은 파이어베이스를 봅니다.

  3. AI — 클로드나 코덱스, 쓰시던 것 아무거나.

04

1단계 · 화면 파일 하나 만들기

여기서는 아직 인터넷도 자료도 없습니다. 화면만 봅니다

컴퓨터에 폴더를 하나 만드십시오. 이름은 dashboard 같은 영어로 하십시오. 그 안에 들어갈 파일은 딱 하나, index.html입니다.

파일 이름은 반드시 index.html

다른 이름이면 주소로 들어갔을 때 화면이 안 뜹니다. 「첫 화면은 index.html」이 인터넷의 약속입니다.

AI에게 이렇게 시키십시오

수학학원 학생관리 대시보드를 만들어 주세요.

조건
- HTML 파일 ★한 개★ 로만 만들어 주세요. CSS·JS를 따로 빼지 말고 그 안에 넣어 주세요.
- 라이브러리는 쓰지 말고 순수 자바스크립트로 해 주세요.
- 자료는 일단 화면 안 변수에 넣어 두고, 나중에 파이어베이스로 옮길 수 있게
  자료를 읽고 쓰는 함수를 한군데로 모아 주세요.

첫 판에 넣을 것
- 학생 목록 (이름·학년·학교·반)
- 반별 출석 체크 (날짜 고르면 그 반 학생이 쭉 나오고 출석/결석/보강 단추)
- 학생 한 명을 누르면 그 학생의 출석 기록이 보이는 화면

한글로 만들고, 휴대폰에서도 보이게 해 주세요.

나온 파일을 index.html로 저장하고 더블클릭해 보십시오. 브라우저에 화면이 뜹니다. 마음에 안 드는 데를 AI에게 말해서 몇 번 고치십시오. 이 단계에서 완벽하게 만들려고 하지 마십시오. 어차피 나중에 백 번 고칩니다.

왜 파일 한 개로 하나

파일이 여럿이면 올릴 때도 고칠 때도 「어느 파일이었지」가 됩니다. 한 개면 그 고민이 없습니다. 1만 줄이 넘어가도 AI는 잘 다룹니다. 김병진T도 9,800줄짜리 한 개로 쓰고 계십니다.

05

2단계 · 깃허브에 올리기

가장 낯선 데입니다. 그래서 제일 자세히 적습니다

깃허브에는 명령어로 올리는 법과 웹에서 끌어다 놓는 법이 있습니다. 여기서는 웹에서 끌어다 놓는 법만 씁니다. 김병진T도 이 방법으로 하고 계십니다. 명령어는 배울 것이 많고, 안 배워도 아무 지장이 없습니다.

① 저장소 만들기

  1. 깃허브에 로그인 → 오른쪽 위 ＋ → New repository
  2. Repository name에 dashboard 라고 적으십시오
  3. Public을 고르십시오 (아래 설명 참고)
  4. 맨 아래 Create repository

Public 이 걸리실 겁니다

화면 파일은 공개돼도 됩니다. 거기에는 학생 정보가 없고, 화면을 그리는 코드만 있습니다. 학생 정보는 파이어베이스에 들어가고 그건 공개되지 않습니다. 화면과 자료를 갈라 놓는 까닭이 여기에도 있습니다.

Private으로 두면 무료 깃허브 페이지가 안 됩니다. 그래도 걱정되시면 12번을 먼저 읽으십시오.

② 파일 올리기

  1. 만든 저장소 화면에서 Add file → Upload files
  2. index.html을 끌어다 놓으십시오 (파일 탐색기에서 그대로 드래그)
  3. 아래 Commit changes 초록 단추를 누르십시오

Commit = 「이대로 저장」. 누를 때마다 그 시점이 기록으로 남습니다.

Commit 이 왜 중요한가

커밋을 누를 때마다 그때의 파일 전체가 통째로 보관됩니다. 한 달 뒤에 무언가 망가져도 Commits에서 잘 되던 날로 돌아가 그 파일을 받아 올 수 있습니다. 이게 「내 컴퓨터에만 두는 것」과 결정적으로 다른 점입니다.

한 번에 100개까지

웹 업로드는 한 번에 100파일이 한도입니다. 해설 이미지처럼 파일이 많으면 나눠 올리십시오. 그리고 이미지를 먼저, 목록 파일(index.json 같은 것)을 나중에 올리십시오. 순서를 바꾸면 「없는 그림을 가리키는 목록」이 잠깐 살아 있게 됩니다.

3단계 · 인터넷 주소 켜기

1분 걸립니다

  1. 저장소에서 Settings (톱니바퀴)
  2. 왼쪽 목록에서 Pages
  3. Source를 Deploy from a branch로
  4. 바로 아래 Branch를 main / /(root)로 두고 Save

https://내아이디.github.io/dashboard/

휴대폰으로도 열어 보십시오. 여기까지 오시면 절반은 끝났습니다. 이제 이 주소는 없어지지 않습니다.

주소를 즐겨찾기에 넣어 두십시오

휴대폰 홈 화면에 추가해 두면 앱처럼 열립니다. 나중에 학생·학부모에게 줄 주소도 이 아래에 붙습니다.

07

4단계 · 파이어베이스 붙이기

자료가 남기 시작합니다

① 프로젝트 만들기

  1. console.firebase.google.com에 구글 계정으로 들어갑니다
  2. 프로젝트 만들기 — 이름은 아무거나 (예: my-academy)
  3. Google 애널리틱스는 사용 안 함. 필요 없습니다

② 자료 보관함 만들기

파이어베이스 안에 보관함이 두 가지 있습니다. 여기서는 Realtime Database를 씁니다. 김병진T 대시보드가 이걸 쓰고 있고, 처음 배우기에도 이쪽이 쉽습니다.

  1. 왼쪽 빌드 → Realtime Database (Firestore가 아닙니다. 둘이 나란히 있으니 잘 보십시오)
  2. 데이터베이스 만들기
  3. 위치는 싱가포르나 미국 중 아무거나 — 한 번 정하면 못 바꿉니다
  4. 잠금 모드로 시작을 고르십시오 (테스트 모드는 30일 뒤 잠깁니다)

만들고 나면 위에 주소가 하나 뜹니다. 이걸 적어 두십시오.

https://내프로젝트-default-rtdb.firebaseio.com

③ 규칙 넣기 — 이게 제일 중요합니다

규칙 탭에서 안의 내용을 지우고 아래를 붙여 넣은 뒤 게시를 누르십시오.

{
  "rules": {
    ".read": "auth != null",
    ".write": "auth != null"
  }
}

「로그인한 사람만 읽고 쓴다」는 뜻입니다.

이 줄을 빠뜨리지 마십시오

「테스트 모드」의 기본 규칙은 아무나 읽고 쓸 수 있게 열려 있습니다. 그 상태로 학생 이름을 넣으면 주소만 알면 누구나 볼 수 있습니다. 규칙을 먼저 넣고 자료를 넣으십시오.

그리고 빌드 → Authentication → 시작하기 → 이메일/비밀번호를 켜고, Users 탭에서 선생님 계정을 하나 만드십시오. 그 계정으로만 대시보드에 들어갑니다.

④ 열쇠 꺼내기

  1. 왼쪽 위 톱니바퀴 → 프로젝트 설정
  2. 일반 탭 맨 아래 「내 앱」에서 웹 </> 단추
  3. 닉네임 아무거나 적고 앱 등록 (호스팅은 체크하지 마십시오)
  4. 나오는 firebaseConfig 덩어리를 통째로 복사하십시오

apiKey가 공개돼도 괜찮습니다

파이어베이스의 열쇠는 비밀번호가 아니라 「어느 집 문인지」를 가리키는 주소표입니다. 실제로 막는 것은 ③의 규칙입니다. 그래서 이건 깃허브에 올라가도 됩니다. 다만 규칙을 안 넣으면 주소표만으로 문이 열립니다. 그래서 ③이 제일 중요합니다.

⑤ 화면에 붙이기

AI에게 index.html과 복사한 firebaseConfig를 함께 주고 이렇게 말하십시오.

이 대시보드에 파이어베이스 Realtime Database 를 붙여 주세요.
설정값은 아래와 같습니다.

[여기에 firebaseConfig 붙여넣기]

- Firestore 말고 ★Realtime Database★ 로 해 주세요
- SDK 는 firebasejs 10.12.0 의 ★compat 방식★ 으로 써 주세요
  (firebase-app-compat.js / firebase-auth-compat.js / firebase-database-compat.js)
- 지금 화면 안 변수에 있는 자료를 firebase.database().ref(...) 로 읽고 쓰게 바꿔 주세요
- 이메일/비밀번호 로그인을 붙여서, 로그인 안 하면 화면이 안 보이게 해 주세요
- 파일은 여전히 ★한 개★ 로 유지해 주세요

compat 방식으로 하시는 까닭

같은 파이어베이스를 쓰는 길이 두 가지인데, compat 쪽이 코드가 훨씬 짧고 읽기 쉽습니다. firebase.database().ref('students').set(...) 처럼 읽으면 뜻이 보입니다. AI가 가끔 새 방식으로 짜 놓으니 위 문장을 그대로 넣어 주십시오.

나온 파일을 다시 2단계처럼 올리십시오. Add file → Upload files → 드래그 → 같은 이름이면 덮어씁니다 → Commit.

여기까지가 산입니다

  2. 학생을 한 명 넣고 저장
  3. 휴대폰으로 같은 주소를 열어 그 학생이 보이는지
  4. 파이어베이스 콘솔의 Realtime Database에 그 학생이 들어와 있는지

네 개가 다 되면 끝났습니다. 남은 것은 기능을 늘리는 일이고, 그건 아래 되풀이일 뿐입니다.

09

이제부터는 이것의 되풀이

기능을 백 개 붙여도 이 넷을 도는 것뿐입니다

01말한다AI에게 파일을 주고 「이걸 이렇게 고쳐 줘」
02본다받은 파일을 더블클릭해서 내 컴퓨터에서 먼저 확인
03올린다Add file → Upload files → 드래그 → Commit
04새로고침1~2분 뒤 주소에서 Ctrl+F5

출결을 붙이든, 자동채점을 붙이든, 학부모 리포트를 붙이든 이 넷입니다. 2단계에서 겪으신 그 낯섦은 딱 한 번입니다.

02를 건너뛰지 마십시오

내 컴퓨터에서 먼저 열어 보는 것이 가장 싼 검사입니다. 안 보고 올리면 「올렸는데 안 되네 → 다시 고쳐 → 다시 올려」로 시간이 배로 듭니다.

고치실 때 AI에게 말하는 요령

나쁜 말 — 「출석 부분 고쳐 줘」

좋은 말 — 「출석 화면에서 날짜를 고르면 그 반 학생만 나와야 하는데 지금은 전체가 나옵니다. 반을 고르는 칸을 위에 하나 더 넣고, 고른 반 학생만 보이게 해 주세요.」

무엇이 · 지금 어떤데 · 어떻게 돼야 하는지 셋을 적으면 한 번에 됩니다.

10

자주 나는 탈

이럴 때이렇게
올렸는데 화면이 그대로Ctrl+F5(맥은 ⌘+Shift+R). 브라우저가 옛 파일을 물고 있는 것입니다. 그래도 안 되면 2분 더 기다리십시오.
주소를 열면 404파일 이름이 index.html인지, Settings→Pages가 main / (root)인지 보십시오.
permission_denied
가 뜬다		파이어베이스 규칙이 로그인을 요구하는데 로그인이 안 된 것입니다. Authentication에 계정을 만드셨는지, 그 계정으로 들어갔는지 보십시오.
자료가 안 보인다브라우저에서 F12 → Console을 열어 빨간 글씨를 통째로 복사해 AI에게 주십시오. 대부분 그 한 줄로 잡힙니다.
고치다 완전히 망가졌다깃허브 저장소 → Commits → 잘 되던 날 → <> → 그 파일을 받아 다시 올리십시오. 이래서 깃허브를 씁니다.
파일이 100개가 넘는다나눠 올리십시오. 이미지 먼저, 목록 파일 나중에.
11

다음에 하면 좋은 것

첫 화면이 뜬 뒤에

붙일 것왜
학생용 화면파일을 하나 더 만들어 같은 파이어베이스를 보게 합니다. 숙제 제출·자동채점이 여기서 나옵니다.
학부모 링크parent.html?id=학생ID 꼴로 학생마다 다른 주소를 줍니다. 월간 현황을 보냅니다.
자동채점교재별 정답표를 넣어 두면 학생이 답만 넣어도 채점됩니다.
오답 유형분석문항마다 「유형」을 붙여 두면 틀린 것이 유형별로 묶입니다. 여기서부터 다른 학원과 갈립니다.
Vercel깃허브 페이지 대신 씁니다. 깃허브 계정으로 로그인해 저장소를 고르면 끝이고, 올린 뒤 반영이 더 빠릅니다. 김병진T는 이걸 씁니다.

순서를 지키십시오

처음부터 자동채점을 만들려 하면 두 달이 갑니다. 학생 목록 → 출결 → 테스트 점수 → 자동채점 → 유형분석 차례로 붙이십시오. 앞의 것이 서 있어야 뒤의 것이 붙습니다.

12

학생 정보는 이렇게

이건 기능이 아니라 지켜야 할 선입니다

  • 깃허브에 올라가는 파일에 학생 이름·전화번호를 넣지 마십시오. 그건 공개됩니다. 학생 정보는 파이어베이스에만 둡니다.
  • 파이어베이스 규칙을 반드시 넣으십시오. 「로그인한 사람만」 한 줄입니다.
  • 학부모 링크는 추측하기 어려운 아이디를 쓰십시오. ?id=1, ?id=2는 옆집 학생 것이 열립니다.
  • AI에게 파일을 줄 때 학생 이름이 박혀 있으면 지우고 주십시오. 시험 삼아 넣은 이름은 「학생1·학생2」로 두는 것이 낫습니다.

한 번만 확인하십시오

파이어베이스 콘솔에서 Realtime Database → 규칙 탭을 열어 보십시오. ".read": true 또는 ".write": true 라고 되어 있으면 주소를 아는 누구나 학생 자료를 보고 지울 수 있습니다. "auth != null" 로 되어 있어야 맞습니다.

막히시면 어느 단계 몇 번에서 무엇이 어떻게 안 되는지 단톡에 적어 주십시오. 화면을 캡처해 주시면 더 빠릅니다.
